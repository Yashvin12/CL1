--------------------------------------------------------------------------------
3. THEORETICAL BACKGROUND
--------------------------------------------------------------------------------
3.1 DECISION TREE
A Decision Tree is a flowchart-like structure where each internal node represents
a feature test, each branch represents the test outcome, and each leaf node holds
a class label. It splits data based on the feature that maximizes information gain.

Limitation: A single decision tree is prone to overfitting (high variance).


3.2 RANDOM FOREST (Ensemble Learning)
Random Forest is an ensemble method that builds multiple decision trees and
combines their predictions by majority voting (classification).

Key principles:
a) Bagging (Bootstrap Aggregating):
   Each tree is trained on a random bootstrap sample (sampling with replacement)
   from the training data. Different trees see different subsets of data.

b) Feature Randomness:
   At each split in each tree, only a random subset of features (√n_features)
   is considered. This decorrelates the trees, reducing variance.

c) Aggregation (Voting):
   Final prediction = majority vote across all n_estimators trees.
   More trees = more stable, less overfitting.

Why Random Forest > Single Decision Tree:
   - Reduces overfitting through averaging many uncorrelated trees.
   - More robust to noisy data.
   - Provides feature importance scores.


3.3 LABEL ENCODING
The Car Evaluation dataset is entirely categorical (e.g., "low", "med", "high").
Machine learning models require numerical inputs, so LabelEncoder converts each
unique category to an integer:
    low→0, med→1, high→2, vhigh→3 (order determined alphabetically)
A separate encoder is stored for each column to allow inverse transformation.


3.4 FEATURE IMPORTANCE
Random Forest provides a built-in feature importance score based on the mean
decrease in Gini impurity each feature achieves across all trees. Higher score
= feature has more predictive power.


3.5 EVALUATION METRICS (Multi-Class)
   Accuracy   = Correct Predictions / Total Predictions
   Precision  = TP / (TP + FP)  — per class
   Recall     = TP / (TP + FN)  — per class
   F1-Score   = 2 * P * R / (P + R)  — harmonic mean of Precision and Recall
   Confusion Matrix: 4×4 matrix showing actual vs. predicted class counts.

7. ANALYSIS & DISCUSSION
--------------------------------------------------------------------------------
1. The Random Forest achieved 98.27% accuracy on a 4-class imbalanced dataset,
   demonstrating the power of ensemble methods.

2. 'unacc' (unacceptable) achieved near-perfect recall of 1.00, as it dominates
   the training data (70%). The model is highly confident at identifying bad cars.

3. 'good' and 'vgood' classes are underrepresented (~4% each), yet the model
   still achieved 93% and 96% F1-scores respectively — a sign that Random Forest
   handles class imbalance better than a single decision tree.

4. Feature importance reveals:
   - Safety and Persons are most decisive — unsafe or low-capacity cars are
     immediately flagged as unacceptable.
   - Doors contribute the least, as having 2–5 doors rarely determines quality.

5. Stratified splitting was important because the dataset is imbalanced. Without
   stratify=y, some minority classes (good, vgood) might be underrepresented in
   the test set, giving misleading accuracy figures.

8. VIVA QUESTIONS & ANSWERS
--------------------------------------------------------------------------------
Q1. What is Random Forest and how is it different from a Decision Tree?
Ans: Random Forest is an ensemble of multiple decision trees. Each tree is trained
     on a random bootstrap sample and uses a random subset of features at each split.
     Final prediction is made by majority vote. A single decision tree overfits;
     Random Forest reduces variance by averaging many diverse trees.

Q2. What is Bagging?
Ans: Bootstrap Aggregating (Bagging) — each tree is trained on a different random
     sample (with replacement) of the training data. This creates diversity among
     trees, reducing correlation and improving generalization.

Q3. Why is Label Encoding used here instead of One-Hot Encoding?
Ans: Decision-tree-based models (including Random Forest) can handle ordinal
     integer-encoded data without assuming linear relationships between encoded
     values. Label encoding is simpler and faster for tree-based models.

Q4. What does feature importance mean in Random Forest?
Ans: Feature importance measures how much each feature reduces impurity (Gini)
     averaged across all trees. Higher importance = feature is more useful for
     splitting. In this experiment, 'safety' is most important (0.278).

Q5. How does Random Forest handle overfitting?
Ans: By training each tree on a different random subset of data (bagging) and
     considering only random feature subsets at each split, the trees become
     uncorrelated. Averaging uncorrelated predictions cancels out individual
     errors, reducing overfitting.

Q6. What is stratified splitting and why is it used?
Ans: Stratified splitting ensures that the proportion of each class in the
     train and test sets matches the original dataset. It is crucial for
     imbalanced datasets (like this one where 'unacc' = 70%) to prevent
     misleading evaluation results.
